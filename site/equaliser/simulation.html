The model is still linked by an absolute path

Each op amp’s ModelFile in BandA.asc points at a folder on the machine the file was drawn on:

C:\Users\ebul0\Downloads\sbom627d\OPA164x.LIB

On anyone else’s machine the simulation stops with “This sub-circuit name is not defined”. A copy of the library is already committed beside the schematic, at LT_SPICE/BandA/OPA164x.LIB. Point the model at that with a relative path and it will run anywhere. The hpf, lpf and gain models use LTspice’s built-in op amp, so they run as they are.

How this site works out the response

LTspice is not available where this site is built, so the response on the bands page is worked out from the KiCad sheet directly by build/_eq_response.py. It reads the netlist, splits each pot at its wiper into two resistors, treats each op amp as a gain of a million, and solves the circuit at 401 frequencies from 10 Hz to 100 kHz — the same nodal analysis SPICE does for an AC run.

Ideal op amps are a fair assumption here. The OPA1644 has 11 MHz of gain-bandwidth; at 20 kHz that still leaves it hundreds of times more gain than any stage asks for. What it cannot show is noise, headroom or the op amps’ own distortion — those need the real model, or a real board.

Re-running BandA

  1. Open Low_Bandpass_Filter/LT_SPICE/BandA.asc in LTspice.
  2. Fix the model path as above.
  3. Run. The analysis is already set: .ac dec 100 10 100k.
  4. Plot V(output). With the file’s pot settings it should peak at +9.5 dB near 1.26 kHz.

To try other knob positions, change the resistor pairs standing in for each pot (R4/R5 width, R9/R10 and R13/R14 frequency, R18/R19 boost/cut), keeping each pair’s sum at 10k.
