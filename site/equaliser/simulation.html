Simulating it

The site solves the whole sheet; the team’s LTspice model of the low-mid band agrees with it.

How this site works out the response

LTspice is not available where this site is built, so every response on these pages is worked out from the KiCad sheet directly by build/_eq_response.py. It reads the netlist, splits each pot at its wiper into two resistors, treats each op amp as a gain of a million, and solves the circuit at 401 frequencies from 10 Hz to 100 kHz — the same nodal analysis SPICE does for an AC run. It starts at the INA137’s output and ends at the DRV134’s input; the receiver’s −6 dB and the driver’s +6 dB cancel, so that is also the module’s response from input to output.

The four frequency pots are on the top board, connected through J2 and J3; the solver joins the two headers pin for pin, as the wiring between the boards does.

Ideal op amps are a fair assumption here. The OPA1644 has 11 MHz of gain-bandwidth; at 20 kHz that still leaves it hundreds of times more gain than any stage asks for. What it cannot show is noise, headroom or the op amps’ own distortion — those need the real model, or a real board.

With every knob centred the response should be a straight line. It is within 0.54 dB from 20 Hz to 20 kHz, and the rise towards 12 kHz is C33 (see the shelves).

The BandA model is linked by an absolute path

Each op amp’s ModelFile in BandA.asc points at a folder on the machine the file was drawn on:

C:\Users\ebul0\Downloads\sbom627d\OPA164x.LIB

On anyone else’s machine the simulation stops with “This sub-circuit name is not defined”. A copy of the library is already committed beside the schematic, at LT_SPICE/BandA/OPA164x.LIB. Point the model at that with a relative path and it will run anywhere.
